# 셀러마진 · 온라인 셀러 마진·광고 손익분기 계산기

스마트스토어, 쿠팡 마켓플레이스, 11번가, 자사몰(그리고 Etsy·Amazon FBA 단순화 예시)에서 상품 한 개를 팔았을 때 **실제로 남는 돈(순마진)**과 **광고비를 얼마까지 쓸 수 있는지(손익분기 광고비, 손익분기 ROAS)**를 계산하는 정적 웹 앱입니다.

- 빌드 과정 없음: HTML, CSS, ES 모듈, localStorage만 사용합니다. 외부 스크립트·폰트·CDN은 쓰지 않습니다.
- 계산 결과는 참고용 추정치이며 세무·법률·재무 자문이 아닙니다.

## 기능

1. **상품 관리**: 상품명, SKU, 채널, 판매가, 원가, 포장비, 배송비 부담액, 반품률, 반품 1건당 추가 손실, 광고비(주문당 금액 또는 목표 ROAS), 월 판매량.
2. **채널 수수료 (편집 가능)**: 판매 수수료 %, 결제/PG 수수료 %, 주문당 고정 수수료, 부가세 분리 ON/OFF. 기본값은 **예시 수수료**이며 "예시 수수료 · 직접 확인 필요 · 기준일 2026-11" 라벨이 붙어 있습니다. 공식 요율이 아닙니다.
3. **상품 상세**: 순마진, 마진율, 손익분기 ROAS, 손익분기 광고비/주문, 목표 마진율을 맞추는 판매가(역산), 반품 반영 기대 마진, 정산 내역, 채널별 비교.
4. **시뮬레이션**: 판매가, 할인율, 쿠폰, 원가, 주문당 광고비, 반품률을 슬라이더로 바꾸면 기준값 대비 변화가 바로 표시됩니다. 저장되지 않습니다.
5. **상품 표**: 순마진, 마진율, 손익분기 ROAS 기준 정렬, 적자만 보기, 검색.
6. **CSV 가져오기**: 붙여넣기 또는 파일 선택. 행별 오류를 줄 번호와 함께 보여 주고, 통과한 행만 추가합니다. 수식 주입을 막기 위해 `=`, `+`, `-`, `@`로 시작하는 문자열은 내보낼 때 앞에 `'`을 붙입니다.
7. **요약 대시보드**: 월 판매량 기준 월 예상 순이익, 광고비 총액, 월 예상 마진율. 경고는 "적자 판매 중인 상품 수"와 "마진율 < 목표 상품 수"를 셉니다.
8. **내보내기**: 상품 CSV, 계산 결과 CSV, JSON 백업(가져오기 시 덮어쓰기 확인).
9. **AI 개선안** (선택): 아래 "AI 기능" 참고.
10. **시나리오 비교**: 기준, 프로모(할인율 설정), 광고 강화(주문당 광고비 배율 설정)를 나란히 계산합니다. 프로모 할인율(0~50%)과 광고 배율(1~10배)은 저장되어 다음 방문에도 유지됩니다.
11. **민감도 표**: 판매가(기준의 0.8~1.2배) × 목표 ROAS(2~6배) 격자에서 마진율과 순마진을 보여 줍니다. 광고비는 판매가 ÷ ROAS, 할인·쿠폰은 적용하지 않습니다.
12. **손익분기 차트**: 주문당 광고비에 따른 순마진 직선을 인라인 SVG로 그리고, 손익분기 광고비와 현재 광고비 위치를 표시합니다.
13. **채널별 월 손익**: 상품 1개당 금액 × 월 판매량을 채널별로 합산합니다(매출, 원가, 포장·배송, 수수료, 반품 손실, 광고비, 순이익). 월 판매량을 입력한 상품만 반영됩니다.
14. **CSV 오류 목록**: 검사에서 걸린 행의 줄 번호와 이유를 CSV 파일로 내려받을 수 있습니다.
15. **테마**: 상단 버튼으로 자동(시스템 설정) · 밝게 · 어둡게를 고를 수 있습니다. 선택은 이 브라우저에 저장됩니다.

## 계산 규칙

모든 금액은 원 단위 정수입니다. 0.5는 절대값 기준으로 올림합니다(`rnd`). 중간값은 실수로 두고 금액 항목마다 한 번만 반올림합니다.

| 항목 | 규칙 |
|---|---|
| 할인 후 판매가 | `반올림(판매가 × (100 − 할인율) / 100) − 쿠폰`, 음수는 0 |
| 부가세 (분리 ON) | `반올림(판매가 × 0.1 / 1.1)`. 매출 = 판매가 − 부가세 |
| 부가세 (분리 OFF) | 부가세 0. 판매가 전액을 매출로 봅니다 |
| 판매 수수료 / 결제 수수료 | 할인 후 판매가 × 수수료 %, 원 단위 반올림. 기준은 부가세 포함 결제금액 |
| 반품 없을 때 광고 전 이익 | 매출 − 원가 − (포장비 + 배송비 부담) − (판매 수수료 + 결제 수수료 + 고정 수수료) |
| 반품 1건일 때 광고 전 이익 | −(포장비 + 배송비 부담 + 수수료 합계 + 반품 1건당 추가 손실). 원가는 재입고, 매출은 환불, 수수료·포장·배송은 환불되지 않는다고 가정 |
| 기대 광고 전 이익 | (1 − 반품률) × 반품 없을 때 + 반품률 × 반품 1건일 때 |
| 광고비 / 주문 | 주문당 입력값, 또는 목표 ROAS 모드면 `반올림(할인 후 판매가 / 목표 ROAS)` |
| 순마진 | 기대 광고 전 이익 − 광고비 / 주문 |
| 마진율 | 순마진 ÷ 매출(부가세 제외, 반품 전) × 100 |
| 손익분기 ROAS | 할인 후 판매가 ÷ 기대 광고 전 이익. 광고 전 이익이 0 이하이면 "없음" |
| 손익분기 광고비 / 주문 | 기대 광고 전 이익 (0 이하이면 광고 전 적자) |
| 상태 | 순마진 < 0 → 적자, 마진율 < 목표 마진율 → 위험, 그 밖은 양호. 매출 0 이하는 "입력 확인" |
| 목표 마진율 역산 판매가 | 마진율을 만족하는 최소 정수 판매가를 이분 탐색(상한 1억 원). 도달 불가면 "도달 불가" |
| 월 예상 순이익 | Σ(순마진 × 월 판매량) |

- 목표 마진율은 사용자 설정값이며 기본 15%입니다.
- 원가·포장비·배송비는 **부가세를 뺀 금액**으로 입력한다고 가정합니다(매입세액 공제 반영). 이 가정이 맞지 않으면 결과가 달라집니다.

### 상수와 출처 (코드: `logic.js`의 `CONSTANTS`)

| 상수 | 값 | 기준 / 출처 | 비고 |
|---|---|---|---|
| `VAT_RATE` | 0.1 | 부가가치세 일반과세 표준세율, 적용 연도 2026 | 법령 개정 시 수정 |
| `AS_OF_DATE` | 2026-11 | 예시 수수료 기준일 | 화면 하단에 표시 |
| `DEFAULT_TARGET_MARGIN` | 15 | 앱 기본 목표 마진율 (법적 값 아님) | 사용자가 변경 |
| `CHANNEL_PRESETS` | 6개 채널 | **예시 값**, 공식 요율 아님 | 직접 확인 필요 |
| `MAX_PRICE`, `MAX_MONEY` | 1억 원 | 입력 검증 상한 | 앱 내부 값 |
| `MAX_VOLUME` | 1,000,000 | 월 판매량 입력 상한 | 앱 내부 값 |

예시 채널 값은 `logic.js`에서 확인하고 수정하세요. 화면에서도 채널 수수료 표에서 바로 고칠 수 있습니다.

## 실행 방법

```bash
cd sellermargin
python3 -m http.server 8121
# 브라우저에서 http://localhost:8121/ 열기
```

`file://`로 열면 ES 모듈이 차단되므로 반드시 HTTP 서버로 여세요. 포트는 8121~8129 범위에서 골라 쓰면 됩니다.

## 테스트

```bash
node --test tests/logic.test.js
```

Node 18 이상이면 됩니다(`package.json`에 `"type": "module"` 설정). 테스트는 다음을 다룹니다.

- 정수 원 반올림, 0.5 처리, −0 방지 (테스트 50개 통과 기준)
- 금액·퍼센트·ROAS·월 판매량 파싱 경계 (0, 음수, 소수, 범위 초과, 빈 값)
- 수수료 스택: 부가세 분리 ON/OFF, 고정 수수료, 반품 기대값, 할인·쿠폰, 목표 ROAS 모드
- 0 나눗셈: ROAS 목표 0, 광고비 0, 광고 전 적자, 할인 100%, 반품률 100%
- 반품률 0~100% 경계
- 역산 판매가 속성 테스트: 무작위 입력 300건에서 역산 판매가는 목표를 만족하고 한 원 낮은 가격은 만족하지 않음 (도달 불가 케이스도 검증)
- CSV: BOM, CRLF, 따옴표 이스케이프, 줄바꿈 포함 필드, 닫히지 않은 따옴표, 헤더 누락, 행별 오류와 줄 번호, 수식 주입 방지
- 백업 JSON 검증: 버전 불일치, 잘못된 행 제외, 목표 마진율 범위 복원
- AI: 키 형식 검사, 프롬프트에 상품명이 기본으로 빠지는지, 응답 파싱(코드펜스·설명 텍스트 제거, 타입 보정, 길이 제한), 규칙 기반 조언
- 시나리오: 설정 범위 검증, 기준·프로모·광고 강화 계산 (광고 배율은 ROAS 모드에도 적용)
- 민감도 표: 격자 셀이 같은 조건의 `computeProduct` 결과와 일치, ROAS가 높을수록 순마진이 같거나 큼
- 채널별 월 손익: 매출 − 원가 − 포장·배송 − 수수료 − 반품 손실 − 광고비 = 순이익 항등식이 채널별·합계 모두 오차 없이 성립
- 손익분기 차트 모델: 직선 끝점, 손익분기 점, 0 눈금 포함, -0 없음, 광고 전 적자일 때 점 없음
- CSV 오류 보고서: 행 번호와 수식 주입 방지

## 데이터와 개인정보

- 모든 데이터(상품, 채널, 설정)는 이 브라우저의 `localStorage`(키: `sellermargin-state`)에만 저장됩니다. 서버로 보내지 않습니다.
- 저장소를 지우거나 기기를 바꾸기 전에 **JSON 백업**을 내려받으세요. 가져오기는 현재 데이터를 덮어씁니다.
- 저장 공간을 쓸 수 없는 환경(사생활 보호 창 등)에서는 저장되지 않는다는 안내를 표시하고, 화면은 계속 동작합니다.

## AI 기능

- **전송되는 내용**: 순마진이 가장 낮은 상품 최대 5개의 숫자 요약입니다(판매가, 순마진, 마진율, 손익분기 ROAS, 주문당 광고비, 반품률, 월 판매량)와 목표 마진율. **상품명과 SKU는 기본으로 보내지 않습니다.** "상품명을 함께 보내기"를 켜야만 이름이 포함됩니다.
- **미리 보기**: 버튼 옆 "전송될 내용 미리 보기"에서 실제 프롬프트를 확인할 수 있습니다.
- **호출 방식**: 사용자가 버튼을 누를 때만 브라우저가 `https://api.anthropic.com/v1/messages`를 직접 호출합니다. 헤더는 `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`, 모델은 `claude-haiku-5-5`, `max_tokens` 700입니다.
- **API 키**: 사용자가 직접 입력하며 `localStorage`(키: `sellermargin-ai-key`)에 저장됩니다. **브라우저에 저장된 키는 개발자 도구에서 보입니다.** 공용 컴퓨터에서는 저장하지 마세요. 키 형식은 `sk-ant-`로 시작하는지만 확인하며 실제 유효성은 호출 시 확인됩니다.
- **응답 처리**: 모델 응답은 JSON만 허용하고, 파싱 실패·형식 오류는 메시지로 알려 줍니다. 화면 표시는 모두 `textContent`로만 합니다.
- **키가 없을 때**: "키 없이 규칙 기반 분석"을 누르면 같은 화면 구성으로 규칙 기반 조언이 나옵니다. 가격 역산 결과로 "얼마 올리면 목표 마진에 가까운지", "광고비 상한은 얼마인지", "반품률이 높은지"를 알려 줍니다. API를 호출하지 않습니다.

## 수익화 메모 (구현하지 않음)

- 제안 가격: 개인 셀러용 월 구독 약 9,900원, 소규모 팀용 월 약 29,000원. 가격은 시장 조사 전 가설입니다.
- 무료 범위: 상품 30개 이하, 채널 수수료 편집, 개별 계산, 브라우저 저장, 규칙 기반 조언.
- 유료 범위: 상품 무제한, CSV 대량 가져오기, 월간 손익 리포트, 여러 기기 동기화(서버 저장 도입 시), AI 개선안 전용 크레딧.
- 결제 기능은 이 저장소에 구현하지 않았습니다. 결제 도입 시 개인정보 처리 방침과 전자상거래 관련 고지가 필요합니다.

## 한계와 확인 필요 사항

- 예시 수수료, 정산 주기, 반품 시 수수료 환불 여부는 채널마다 다릅니다. 앱의 가정과 맞는지 직접 확인하세요.
- 부가세 처리는 단순화했습니다. 실제 신고 기준(과세 유형, 매입세액 공제, 면세 품목)은 세무 전문가와 확인하세요.
- 광고비는 주문당 금액으로 봅니다. 노출·클릭 단위의 실제 광고 구조는 반영하지 않습니다.
- AI 호출은 실제 키와 네트워크가 있는 환경에서 직접 확인해야 합니다. 저장소의 테스트는 네트워크 호출을 하지 않습니다.
